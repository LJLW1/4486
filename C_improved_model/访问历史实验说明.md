# 时间基线与访问历史实验

`visit_history_model.py` 是独立脚本，可在 notebook 导入；不需要项目中的 `common` 模块。原有 `basic_model_submission.ipynb` 未改动。

## 本地复现

从项目根目录运行：

```bash
OPENBLAS_NUM_THREADS=1 python3 C_improved_model/visit_history_model.py --validate
```

默认使用项目原始比赛数据和 `artifacts/shared/patient_folds.csv`，支持 `--data-dir`、`--folds` 和 `--output-dir`。输出在 `validation_results`：逐请求折外预测、按量表和预测时长的明细，以及汇总指标。每折患者互不重叠；标签用训练患者的临床数据，评分是 200×|预测−真实|/(预测+真实+2)，越低越好。

| 模型 | 五折均值 | 合并折外得分 |
| --- | ---: | ---: |
| 已通过版本的时间基线 | 65.055 | 64.880 |
| 访问历史：临床与组学访问并集 | 58.584 | 58.449 |
| 访问历史：仅组学访问 | 65.214 | 65.030 |

以组学访问作为预测起点，保留在目标月份存在标签的请求。临床+组学并集是训练数据对 API 可见访问的模拟：训练端将临床访问当作 test 表中的访问，组学访问当作蛋白/肽表中的访问。真实隐藏测试可能有不同的访问或缺失机制；仅组学结果是诊断对照，并非最终 API 回放的等价模拟。训练和验证的样本构造也可能与隐藏集不同。既有折已用于探索，以上不是独立测试或竞赛分数。

历史特征记录当前时间之前（含当前批次）是否观察到第 6、18 个月的访问；不使用临床量表分数、蛋白丰度或未来访问。每个量表的预测选择使时间加权经验 SMAPE 最小的整数；未出现过的历史类别回退到该量表全部训练样本。当前基线和历史模型均按既有 notebook 的组学访问起点生成训练请求，不改变官方 API。

## 在 Kaggle notebook 中调用

将 `visit_history_model.py` 作为 Kaggle Dataset 输入上传并添加到 notebook，保留比赛数据源、关闭 Internet。将下方脚本目录改成 Kaggle 上该文件所在目录：

```python
import sys
sys.path.insert(0, '/kaggle/input/你的脚本数据集目录')
from visit_history_model import VisitHistoryModel

model = VisitHistoryModel.from_data_dir('/kaggle/input/amp-pd')

import amp_pd_peptide
env = amp_pd_peptide.make_env()
for test, test_peptides, test_proteins, sample_submission in env.iter_test():
    prediction = model.predict_batch(test, test_peptides, test_proteins, sample_submission)
    env.predict(prediction)
```

同一个模型实例须贯穿所有批次以保留访问历史。`use_history=False` 使用时间基线；`stream='omics'` 则只适合诊断历史训练假设。API 批次要求按访问月份递增，样例满足该条件；若实际数据不满足，脚本会报错而不是使用未来信息。

检查范围：脚本语法通过；公开样例的两个批次、64 条预测已在本地直接重放，时间基线逐行等于已通过 notebook，未来访问截断检查通过。未运行 Kaggle 公开 notebook 或新的隐藏评分，不能声称该历史模型已提交成功。
